An incoming support ticket needs a processing queue. The input is the original notebook's fictional delivery-address message; the output is a ticket ID, intent queue, address-change probability, explicitness score (0–2), and review priority. The program only proposes a queue: it does not modify an order.

Ask all three questions about the same input. A choice needs selected probability ≥ 0.8 and a top-two gap ≥ 0.2 to route automatically. A predicted address change also needs its independent predicate probability ≥ 0.8; disagreement goes to `human_review`. Rank review work by `address_change_probability × explicitness_score / 2`. A score near 2 indicates a more explicit request, not a 100% likelihood of successful fulfillment.

These thresholds illustrate a workflow. They are **not calibrated accuracy guarantees**. Measure false routing costs on your own labeled tickets and tune thresholds before operational use. Ambiguous, novel and low-confidence messages remain reviewable.

## Install and prepare inputs

Use Python 3.11+. Download the small source bundle, extract it, then install its dependencies:

```bash
curl -fLO https://valen-team.github.io/cookbook/valen-cookbook.zip
python -m zipfile -e valen-cookbook.zip .
cd valen-cookbook
python -m pip install -r requirements.txt
```

## Run

```bash
python ticket_routing.py --backend remote --model valen-2b --asset-dir . --output result.json
# An existing local HTTP deployment instead:
python ticket_routing.py --backend remote --base-url http://127.0.0.1:8000/v1 --model valen --asset-dir . --output result.json
```

For direct ONNX execution, use `--backend onnx --model /path/to/Valen-0.8B-ONNX` and first install `valen-sdk[onnx,video]==0.2.0`. Connect a GGUF service through `--backend remote`; a GGUF file is not a `Valen.local` model.
